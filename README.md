# Ориентация текста на изображении

Решение тестового задания Avito Bootcamp: по кропу с текстом определить вероятность
поворота на **180°**. Такой классификатор помогает правильно ориентировать текст
перед распознаванием OCR.

**Результат на лидерборде: 0.96611242 по метрике 1 − Brier.**
Ошибка Брайера — 0.03388758. Итоговый CSV содержит 20 000 строк и две колонки:
`image_id` и `p_180`. Чем выше `p_180`, тем вероятнее, что текст перевёрнут.

## Как устроено решение

1. **Модель:** PP-LCNet x1.0 с готовыми весами для ориентации текстовых строк.
   Вход — RGB-изображение размером 160 × 80, вычисления — FP32.
2. **Данные:** 66 271 кроп из HierText validation и 4 000 синтетических надписей.
   Каждый кроп используется в нормальной и перевёрнутой ориентациях. Найденные
   дубликаты объединяются до разделения сцен на train, development, calibration
   и holdout; seed — 42. RusTitW поддерживается кодом, но в итоговом обучении не использован.
3. **Дообучение:** 6 эпох, batch size 256, начальный LR 0.001.
   В отправленном запуске выбрана эпоха 4 по минимальной cross-entropy на development.
4. **Предсказание:** объединяются ответы модели на кроп и его поворот на 180°:
   `q = (p(x) + 1 − p(rot180(x))) / 2`.
   Затем применяется температура `T ≈ 1.139`, подобранная по Brier на реальной
   части calibration. Веса и температура при повторном инференсе фиксированы.

На реальном development объединение ориентаций снизило Brier с 0.02472064 до
0.02077580. На реальном holdout после калибровки получен score 0.97371928.
Подробное сравнение исходной и дообученной моделей приведено в ноутбуке.
Реальной кириллицы в корпусе мало, поэтому результаты на синтетике показаны отдельно.

## Установка

Нужны **Python 3.12**, [uv](https://docs.astral.sh/uv/getting-started/installation/)
и [Git LFS](https://git-lfs.com/). Для GPU используется PaddlePaddle с CUDA 12.6;
нужны NVIDIA GPU и совместимый драйвер.

```bash
git lfs install
git clone https://github.com/mezgou/avito-bootcamp-test-task.git
cd avito-bootcamp-test-task
git lfs pull
uv sync --locked --extra gpu
```

Git LFS загружает настоящие тестовые изображения и `sample_submission.csv`.
Без него в каталоге данных могут остаться небольшие файлы-указатели.
Все версии зависимостей зафиксированы в `uv.lock`.

Для CPU вместо последней команды выполните `uv sync --locked --extra cpu`
и используйте устройство `cpu`. Дополнения `cpu` и `gpu` устанавливаются по отдельности.

## Запуск ноутбука

Откройте [solution.ipynb](solution.ipynb) в VS Code или Jupyter, выберите ядро
из `.venv/bin/python` и выполните **Run All**. В первой ячейке с кодом задаётся
`DEVICE = "gpu:0"`; для CPU замените значение на `"cpu"`.

Ноутбук показывает сохранённые результаты эксперимента, запускает инференс
и создаёт **`submission.csv` в корне проекта**. Рядом сохраняется `submission.json`
с настройками и временем работы. Затем проверяются формат, все 20 000 ID,
диапазон вероятностей и совпадение с отправленным CSV.

Обучение и подбор температуры повторно не запускаются. Для этого сценария
не нужны `data/external/`, исходные веса до дообучения или промежуточные прогнозы.
Итоговые веса, калибровка, отправленный CSV и сводные отчёты уже включены в репозиторий.
Повторный Run All пересоздаёт только итоговые `submission.csv` и `submission.json` в корне.

## Получить CSV из терминала

Команда выполняет тот же инференс, что и ноутбук:

```bash
uv run --locked --extra gpu python -u -m src.inference.predict \
  --weights outputs/finetune_20260920_175555_827888/best.pdparams \
  --calibration outputs/calibration/finetuned_rotation.json \
  --test-dir data/test \
  --batch-size 256 \
  --read-workers 8 \
  --device gpu:0 \
  --output submission.csv
```

Для повторной записи добавьте `--overwrite`. На CPU замените `--extra gpu`
на `--extra cpu`, а `--device gpu:0` на `--device cpu`.
Параметры устройства передаются явно, поэтому `.env` для этих команд не требуется.

Отправленный файл сохранён в [outputs/submission_calibrated.csv](outputs/submission_calibrated.csv).
Ноутбук сравнивает с ним заново вычисленные вероятности; различия при смене
оборудования или окружения выводятся явно и не заменяются значениями из эталона.

## Скорость и структура проекта

В сохранённом запуске на **RTX 6000 Ada** обработка 20 000 PNG и запись CSV
заняли **17.357 с**, около **1 152 кропов/с**. Загрузка модели и прогрев в замер
не входят. Итоговый файл весов занимает **6.44 MiB**. Ноутбук также показывает
время текущего запуска.

| Путь | Назначение |
| --- | --- |
| `src/data/` | Подготовка внешних данных, синтетики и общая обработка изображений |
| `src/models/` | Архитектура и загрузка весов |
| `src/training/` | Код для новых экспериментов с дообучением |
| `src/evaluation/` | Метрики, оценка и калибровка |
| `src/inference/` | Предсказание и проверка CSV |
| `outputs/` | Итоговые веса, калибровка, отправленный CSV и сохранённые отчёты |

Подготовка дополнительных данных сохраняет результат в `data/external/`.
Новые эксперименты с обучением могут дать другие веса; для повторения отправленного
результата используются файлы, явно указанные в команде выше.

## Источники

Архитектура адаптирована из [PaddleClas](https://github.com/PaddlePaddle/PaddleClas)
с сохранением уведомления Apache-2.0. Использованы официальные веса
`PP-LCNet_x1_0_textline_ori_pretrained.pdparams`; адрес указан в
[src/models/weights.py](src/models/weights.py).
Внешние данные — [HierText](https://github.com/google-research-datasets/hiertext)
(CC-BY-SA-4.0), шрифты синтетики — [DejaVu](https://dejavu-fonts.github.io/).
Основные библиотеки: PaddlePaddle, NumPy, OpenCV, Pillow, pandas, SciPy и Matplotlib.
Инференс выполняется локально, без внешних API и LLM/VLM. Ручная разметка теста не используется.

**Основное решение с пояснениями, результатами экспериментов и получением итогового
CSV находится в [solution.ipynb](solution.ipynb).**
